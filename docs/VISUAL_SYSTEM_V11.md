# AMARELO — Visual System V11

## Objetivo
O AMARELO deve parecer um produto financeiro premium de decisão, não uma coleção de calculadoras, um dashboard bancário genérico ou um template de SaaS.

## Direção
- editorial, sóbrio e contemporâneo;
- amarelo como assinatura e sinal de ação;
- preto quente para profundidade e contraste;
- fundo marfim para reduzir aparência de software corporativo;
- tipografia grande para perguntas e decisões;
- cards com hierarquias diferentes, evitando grade uniforme;
- resultados tratados como workspace de decisão.

## Home
A home apresenta:
1. tese do produto;
2. pergunta em linguagem natural;
3. cockpit visual de uma decisão;
4. jornadas por intenção;
5. metodologia do AMARELO;
6. motores principais;
7. proposta PRO.

O cockpit não representa uma recomendação. É uma representação visual do processo de comparação.

## Biblioteca
- entrada por decisão;
- filtros discretos;
- contagem de resultados;
- cards PRO visualmente distintos;
- estado vazio próprio;
- ação clara sem excesso de botões.

## Meu AMARELO
O dashboard deve comunicar continuidade:
- contexto pessoal;
- decisões salvas;
- favoritos;
- próxima análise;
- estados vazios que orientam, em vez de parecer erro.

## Workspace de decisão
A tela do motor deve ter duas zonas:
- **premissas**, mais neutra e clara;
- **resultado**, escura, com alta hierarquia.

A leitura do resultado segue:
1. resposta;
2. métricas;
3. premissas;
4. significado;
5. break-even;
6. sensibilidade;
7. evolução;
8. salvar / copiar.

## Mobile
- navegação inferior estilo app;
- safe area;
- cards em 1–2 colunas conforme densidade;
- campos grandes e legíveis;
- ações principais sempre claras;
- nenhum conteúdo crítico depende de hover.

## Guardrails
- evitar gradientes decorativos excessivos;
- evitar amarelo como fundo dominante;
- não usar visual de banco tradicional;
- não usar ilustrações genéricas de pessoas com moedas;
- não esconder premissas em tooltips;
- movimento deve ser sutil e respeitar prefers-reduced-motion.
